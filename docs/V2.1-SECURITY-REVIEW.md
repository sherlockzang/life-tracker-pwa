# V2.1 安全检查记录

检查日期：2026-11-12。范围：本地候选代码、依赖审计、生产项目的只读安全建议和临时本地 PostgreSQL 回归。这是针对所检查范围的审查，不是完整渗透测试，也不能证明不存在其他漏洞。

## 结果与处置

1. **触发器函数权限过宽（防御性加固）**：生产安全建议指出 `handle_new_user_profile()` 可由匿名及已登录角色执行。该函数返回 trigger，提示本身不代表已经存在可利用漏洞。迁移撤销客户端直接执行权限；本地临时数据库验证了权限、新用户资料创建和其他隔离测试。2026-11-12 生产迁移后只读检查确认权限已收紧，触发器仍启用。
2. **已登录写入接口**：`save_user_mutation` 需要对已登录用户开放。检查其账号身份、允许的表和字段，临时数据库测试覆盖了跨账号写入、伪造字段和并发冲突；不将其简单关闭。实际线上权限仍应在部署后复核。
3. **RLS 提示**：安全建议中若干开启 RLS 但无客户端策略的表属于服务端专用表，默认拒绝客户端访问；不能仅凭提示判定为漏洞。涉及敏感权限调整应逐项复核。
4. **依赖**：更新兼容范围内的开发／构建依赖后，运行依赖的 npm audit 为 0 项；完整依赖树仍有 12 项（2 低、10 中），位于开发及构建依赖链。未使用可能破坏兼容性的 `npm audit fix --force`；应关注上游修复并定期复查。
5. **密码泄漏保护提示**：当前主要使用邮箱验证码，密码泄漏检查不应被误认作验证码防护；如果启用密码登录，需重新评估并配置相关保护。

## 局限与上线前检查

本地模拟数据库不是生产环境；未进行真实 iPhone 主屏幕 PWA、实际邮箱登录或生产 AI／航班接口的端到端测试。上线前应核对备份、迁移顺序和回滚策略，在隔离环境测试账号及配额，并在生产应用迁移后复查 Supabase 安全建议。公开 Git 历史中的个人信息也不会因为网页移除联系方式而自动消失。
