- 将小号说明文字提升到 13–14px，正文 15–16px，统一表单、按钮与弹窗层级；金额和时间使用等宽数字。
- 首页、设置、交通模板、图表与移动导航共享视觉规则；手机金额移到独立行，避免挤压记录正文。调整币种卡片符号宽度、主题选项和规划内容布局。
- 所有弹窗和快速输入限制可视高度并可滚动，保留安全区域适配与 reduced-motion；键盘焦点可见。
- 抽取 Button、DialogSurface、EmptyState、SettingsRow 等纯展示组件，保留原生按钮类型、回调、禁用状态与业务条件。
- 图表只改变配色、字体和网格线；分类、汇率换算、时间范围与交互未变。
- 应用版本为 2.0.0；准备五条用户可读更新说明与独立 changelog SQL。另有用户追加授权的全天/住宿字段迁移；均未执行，不改账号权限或额度。
- 用户追加授权：时间线增加“撤回完成”“恢复计划”和直接编辑航班/计划的按钮；行程日期范围外的计划也可打开已有编辑器。编辑沿用原有保存流程，演示数据仍只保存到本机。
- 用户追加授权：离线航司目录由 12 家扩充至 114 家，支持中文、英文、简称与 IATA 二字代码搜索。选定航司后可只输入数字部分，保存时仍使用完整航班号；支持 9C、6E 等含数字代码，保留前导零、已有完整号码和代码共享号码，不增加 API 调用。未收录航司可自行填写航司名及完整号码。
- 用户追加授权：新增自动计算计划飞行时长，编辑起降日期、时间或当地时区时实时更新；编辑表单、航班详情与首页航班卡片均显示。复用原有时区换算，先换算为 UTC 再相减，不保存冗余字段、不调用 API；不完整、无效日期或非正时长显示提示，不冒充实际空中飞行时间。编辑表单补充实际匹配入口及 1–48 小时范围的说明。
- 用户追加授权：跨日航班改按起降时间区间在“行程时区”下与旅行日期的重叠归属，而非只比较出发机场当地日期。行程开始前出发、首日抵达的航班只展示在首日，卡片说明真实当地起降日期；完全在范围外的航班仍保留在范围外列表。编辑旅行日期时用新的日期及时区重新校验，单纯重新展示不改动记录。航班同日拖动只更新排序字段；跨日拖动按行程时区平移两地日期，跨边界接入航班另行确认，避免把展示日期直接写成起飞日期。
- 用户追加授权：已完成航班、铁路、市内交通不再划线或弱化标题，改用完成标识；普通待办保留划线样式。实际匹配数据优先显示在航班主视图，时间逐站按“实际 → 预计 → 接口排定 → 原计划”降级，来源明确标注。机型、登机口、注册号优先显示接口值，座位保留手动记录。实际时长按展示的两地时间换算，混有计划值时称为参考用时；原计划折叠保留，不覆盖数据库中的计划字段，不增加自动查询。
- 用户追加授权：增加全天事项与跨日酒店模板、日期范围和独立“全天与住宿”区域。全天结束日包含在展示范围；酒店按入住至退房日之前计算夜晚，退房日单独显示退房提醒。换酒店日并列旧酒店退房、新酒店入住，重叠的过夜安排提示核对；已取消住宿不参与换店/冲突判断。多天只投影同一条记录，编辑/撤回完成作用于整条记录；跨日事项不参与拖拽，日期通过编辑器调整。
- 酒店与全天日期按父行程时区解释，入住/退房时间、预订号、地址和备注为明确标注的选填项。无需新枚举或新表，新增可空 JSONB `records.schedule_details`；旧记录不带该字段仍按原流程读写，新记录用既有保存/离线队列。新增字段需要发布前执行 `20260930010000_all_day_schedules.sql`，RLS 沿用账号隔离，迁移当前只是准备文件。
