## 1. 建立工程

创建React + TypeScript + Vite SPA，npm，Node22.13+，ES module。参考保存package.json及完整package-lock.json、Vite/PWA/TS/ESLint配置；原样恢复锁文件后npm ci，不盲目安装latest。更新依赖须单独安全审查。

基础目录同 README。先实现 types / 数据库 / 纯日期算法，再界面与数据层，再 AI，最后 PWA 与部署。不先用无鉴权的 AI API 做“临时 demo”。

## 2. 功能合同

### 2.1 身份、登录、演示

- 邮箱必填且合法；发送中禁重复提交。收到 6 位码后同页输入，数字键盘、一键码自动填充提示，验证失败可重试/重发/更换邮箱。
- 使用 Supabase Auth OTP，首次自动注册；JWT 自动刷新、会话持久化；前台恢复与 pageshow 查会话，订阅登录/退出变化。
- 没有邮箱密码、Magic Link 主流程、伪登录后门；演示不是绕过 Auth 访问用户库。
- 演示有预置旅程、飞机、普通计划、消费和随记；改动留本地，有演示标识、重置按钮。退出演示不带数据进入真实账号。
- 演示航班返回模拟数据，不请求 Aviationstack；轻量 AI 每设备每日 2 次且服务端受总池限制。首次进入需要获取演示令牌；离线使用已有缓存与 AI 不可用状态区分。
- 新用户引导 5 步可跳过；profile 保存已读，不每次出现。更新弹窗和长期更新记录并存，用数字版本比较，不能字符串比较 1.10 与 1.9。

### 2.2 快速记录与时间线

三种 record_type：

| 类型 | 必填 | 选填 / 限制 |
| --- | --- | --- |
| expense | content、非负金额、币种、分类、event_at | 地点、备注、trip_id、parent_plan_id |
| trip | content、event_at；旅程内有 plan_status | 地点、备注、trip_id、sort_order、结构化模板 |
| note | content、event_at | 备注、trip_id、parent_plan_id；通用图片上传未实现 |

content trim 后 1–4000；只给 expense 存 amount/currency/category，其余清空。用户 ID 必须为当前会话 UUID。默认时间为设备当前时间，可修改；消费金额 0 有效，NaN/负数无效。

首页按最新发生时间倒序，按日期分组，顶部“全部/消费/行程/随记”及数量；隐藏实际子记录，避免同一计划的消费/随记在顶层重复。必要时图表包含全部消费，包括实际子记录。

日期分组和排序必须采用一致的定义：允许选择显示时区，但不得先按 UTC 排序，再用不同航班本地日期决定组顺序而造成 30→28→29。同组内部时间也一致。具体缺陷和期望回归见审查报告。

计划卡有编辑、计划中/已完成/已取消三状态，完成可撤回，取消可恢复；修改保留 id / created_at / owner。普通已完成待办可以划线；交通和酒店作为经历记录不能把标题划掉。通用消费/随记编辑删除不是当前完整功能，勿在用户指南承诺。

### 2.3 旅程与计划

Trip 必填 name / destination / start_date / end_date / timezone；end>=start。目的地文字识别常见城市时区，用户可明确选择标准 IANA 时区；无识别时显示设备默认及提示，不伪装自动匹配成功。

旅程列表当前/未来/过去分组，计划内容按时间先后而非创建顺序。日期按旅程日历生成 Day1…N；不要存 day_number。编辑日期范围有超范围计划时警告，保留并在“日期范围外”区提供编辑，不删除。

按天新增、展开、编辑计划，操作状态；完成计划不自动生成虚构消费。详情能添加实际消费/随记作为 parent_plan_id 子记录，与同一 owner / trip 关联。实际消费保留独立币种金额。

拖动：同天最多调整同一时间内 sort_order，不覆盖时间排序；跨天保留本地时分、变更日期并生成 event_at。航班两端日期同步偏移保留跨日关系；首日“前一天出发”航班跨天移动需要确认。全天/酒店通过编辑范围移动，不提供容易复制坏数据的拖拽。

### 2.4 飞机模板与补全

FlightDetails 合同见 DATABASE 与 types 参考：

- 航司、完整 flight_number；起飞与到达各有 date、time、airport、IATA、terminal、timezone。
- gate / registration / seat / aircraft_type / notes 等选填，界面明确“选填”，空值不要求用户猜。
- 航司字典 114 条：中国、港澳台、日韩、东南亚、欧美、澳新、中东等；支持中文、英文、别名、IATA；不声称囊括全球全部航司。
- 选 ANA → 固定显示 NH 前缀，用户只输 105 → NH105；直接输入 NH105 能逆向识别全日空。数字字母代码 9C、6E、7G 等有效，前导零保留。明确输入其他完整代码时不能强行套旧前缀；不能凭姓名推断实际执飞代码共享航司。
- 机场字典中文/英文/城市/别名/IATA检索；羽田/HND/Tokyo可选东京羽田国际机场，并填Asia/Tokyo；LAX填America/Los_Angeles。未收录机场允许以名称及有效时区保存，仅真实API精确匹配要求两端可信IATA。不能为保存而让用户选错机场。
- 机型输入 78X / B78X / 787-10 都规范为 787-10；B789 / 789 / 787-9→787-9；保存未知机型原文，不猜不同子型号。
- 时长为两端带时区时间的 UTC 差；完整且到达晚于出发才显示，错误不输出负数或 NaN。共享`flightTime`解析器拒绝DST不存在时刻；秋季回拨重复时刻必须明确选择第一次/第二次及UTC偏移。两端分别支持numeric `utc_offset_minutes`（东为正）；没有选择或偏移不属于候选时，保存/匹配均拒绝，不能默认择其一。日期、时间、时区变化清掉原选择；修改偏移也使旧匹配失效。跨日拖动遇歧义时先打开编辑器，不悄悄移动。供应商实际clock只有一致的ISO偏移能证明重复时刻，不继承计划选择，也不据不一致偏移输出确定的实际用时。
- 旅程为 Tokyo 9/29 开始、LAX 9/28 起飞、Tokyo 9/29 到达：首日必须出现航班，标明两端真实日期和“旅程开始前出发”。出行区间完全不相交时保留于范围外。

### 2.5 实际航班匹配

主动按钮在保存后的航班详情，不在未来航班创建表单上浪费请求。资格 = now 在计划到达 UTC+1h 至 +48h 内；前端先检查，服务端用存储计划重查。取消、非法、不完整、未消歧、未来、过窗口均不扣额度并引导手填。

服务端查航班号，仅选 flight_number + 出发当地日期 + departure IATA + arrival IATA 四者完全一致结果；无精确结果不展示其他日期航班。不保证供应商覆盖所有已结束航班，不可把计划到达已过当作供应商状态一定 landed。

先 claim 匹配锁、防重复，再 reserveQuota；查询硬超时14秒覆盖fetch响应头和body读取，超时清状态且不退款；返回30分钟有效预览。AI同样覆盖整响应，deadline为24秒。所有供应商网络错误不能把含密钥URL写进日志。用户确认才写 actual_info，保留原计划；confirm 不调用上游。成功后不在打开页面时重复查询，重新匹配需明确动作。并发只允许一个该记录有效请求。

显示按每端actual > estimated > scheduled > plan；时间、机场、楼、gate、机型、注册号优先匹配值；seat仍为手动值。提供原计划折叠区和来源标签。缺少实际起飞时不能称实际飞行时长。编辑号码/起降日期/时分/IATA/时区使server版本递增，清有效标记与UUID，保留actual历史但不冒充新航段；seat/gate/notes不递增。预览和确认绑定version/owner/record/request；active与confirmed UUID分开。普通JWT不能伪造匹配字段。

上游结果保存失败仍返回内容，短期签名恢复允许仅确认保存，不再次调用航空或预留额度；过期/陈旧版本不能覆盖新计划。兼容旧PWA和旧Edge时必须从可信数据库预览推导版本，不把任意客户端payload认作当前计划。

### 2.6 铁路与市内交通

铁路类型 china_hsr / japan_shinkansen / germany_db / taiwan_hsr / other，自定义系统、车次、出发/到达日期时间站名、座位车厢和备注；摘要优先车次 + 站名。没有铁路实时 API。

市内交通 origin/destination，估计起止时间、route_description、notes；AI 路线建议仅供参考，不是实时地图或票务。结果先展示，用户选应用/保存计划；不要自动订票或自动标记完成。

### 2.7 全天与酒店（本地 V2 新增）

一条记录一个 schedule_details，kind 为 all_day / hotel，不与 transport_details 同时存在。普通记录转换时明确清空旧模板 JSON。

全天 start_date–end_date 为包含两端的范围；酒店 end_date 为退房日，过夜为半开区间 [入住,退房)，必须至少一晚。标题存酒店名/事项，location 地址，notes 补充；check_in_time / check_out_time / booking_reference 选填。

每天单独“全天安排”区域：酒店首日入住，中间续住，末日退房。旧酒店退房与新酒店入住同日显示两条及“换酒店”提醒；仅退房不计该晚住宿，多条非取消过夜记录相交提示确认，取消项不触发重叠警告。范围与旅程相交则展示，不改真实日期。编辑/状态操作修改同一记录，不每日复制。

### 2.8 AI 功能

- 路线：主页和市内交通均为origin/destination双输入；服务端另支持query-only一句话请求，两种合同都有效。地名歧义先请补充，不虚构站点。
- 记账：短描述≤200 字符，解析 amount/currency/category/merchant/note，未知为 null，预览可改，应用表单仍需保存。
- 润色：短文本≤200 字符，不加虚构事实，预览“使用这段”仍需保存。
- 回顾：真实账号自己的已结束旅程，或所有计划已完成；服务器读取数据形成受限摘要，不接收浏览器整包记录作为可信输入；旅行消费按币种表达。缓存按 user/trip，不反复扣费，主动 regenerate 才重算。
- 今日摘要：有今日未取消计划才请求，今日按各活跃旅程当地日；包含当天全天、酒店入住/续住/退房、首日入境航班。缓存按用户及旅程id/当地日/timezone上下文，不因上海午夜而重复生成；上海日期只用于额度/报告锚。无计划skipped；Standard仍1次/上海日。计划变化不自动重算同上下文缓存。
  请求前在IndexedDB v3 automaticSummaries事务领取owner/context；失败/未知结果也留标记，时钟/刷新/前台不自动重试。跨窗口只领取一次、账号隔离、旧标记30天清理。设置可手动生成，不把设备标记当跨设备安全额度。
- 缓存读取不确定时先停止，不浪费模型；生成后缓存/usage失败返回内容与签名恢复凭据，在原账号本地保存副本。重试保存只写数据库不再调用模型或配额，旧副本不能覆盖新缓存；超时仍可复制内容。
- 无 key / 离线 / 超额 / 超时：明确原因、可手动继续，不能阻止基础记录。禁止开放任意 system prompt / 任意模型 / 任意目标 URL。
- 原实现 deepseek-v4-flash / thinking disabled；未来服务更名先查供应商官方支持再换，不能假设永远可用。token 上限 route450 / expense150 / note200 / recap800 / summary300，timeout24s，结构输出验证。

### 2.9 账号、配额、设置

完整配额矩阵见 API 文档；**当前实现普通轻量 AI 每日 15 次**，不是早期讨论的 10 次。每月 10000 为非 Owner **轻量组**共享；回顾/摘要使用独立规则，不在同一桶，不能文案写“所有 AI 绝对总上限 10000”。

设置含主币种13种、theme3种、profile昵称1–40/首字母颜色/2MB头像裁剪WEBP、首次引导、永久更新记录、隐私、致谢、额度。Standard 输入邀请码提升 Friend，Owner 不能由邀请码获得。Owner 后台可邮箱搜索、切换 Standard/Friend、查看月用量，不暴露记录；Owner 行锁定，授权动作服务端记录审计。

隐私文案不得隐瞒外部 AI 会接收用户主动提交的文字，不宣称端到端加密。公开头像不等同私密图片。致谢必须原样：

### 2.10 汇率、离线和 PWA

13 币种：USD JPY EUR GBP CNY HKD SGD KRW AUD NZD CHF CAD THB；六分类 food transport shopping stay entertainment other。汇率采用 direct base→quote 的最新 rate_date，不含中转猜测。请求 /v2/rate/BASE/QUOTE；缺失汇率项暂不计总额并明显提示。

主页7天/30天/全部消费，类别环图、每日柱图、总额/最高类别；统计不是财务凭证，汇率不是每筆交易成交汇率。每日分组不可误用 UTC 日期，见审查项。

离线支持资源加载和已登录缓存记录，操作先入持久队列；AI、初次登录、头像上传需网络。IndexedDB按owner索引，旧无owner数据隔离，账号切换不回放他人操作。队列有pending/inflight/failed/conflict、依赖链及租约；同毫秒编辑也不形成孤儿；成功后子项重基版本。数据库CAS/幂等收据防静默覆盖，RLS等永久错误保留草稿/副本而非显示成功。顶部区分网络和云端确认，可导出本机副本、重试网络失败或AI保存；冲突需核对后编辑，不自动覆盖。恢复前台读真实navigator.onLine及当前会话，不把focus等同在线。

SA-01–SA-05补充合同：只合并明确未发送且无人依赖的项；已尝试/旧v2未知状态保留UUID恢复收据，新编辑成为后继。失败修正继承原CAS，成功后旧副本归档，可导出但不覆盖/重试；失败修正和外部冲突不可静默归档。主页编辑传行程日，不传设备日；非航班拒绝DST跳时，新回拨时刻必选偏移，已有事件保持次序/秒；拖动歧义打开编辑器。date-only新锚取中午，原起始日未变保留锚。详见[自审修复](SELF-AUDIT-FIXES-2026-10-02.md)。

跨实体trip_id/parent_plan_id有独立relationDependencies和拓扑重放；成功只把同实体后继重基CAS，外部实体只清等待。所有完整云端/AI集合用唯一id keyset分页到空页（不以短页结束），全批成功才替换缓存；旧失败/冲突草稿仍叠加显示，legacy隔离。数据库拒绝有子项父计划的破坏关系修改，子项锁父行防并发竞态。配额读取任何分支失败返回503，不造余额；月末先在上海本地日历计算再转UTC。详见[独立审计修复](AUDIT-FIXES-2026-10-02.md)。

PWA manifest standalone；192/512 PNG、180 Apple touch icon、正式方形 Logo；base/start_url/scope 统一。viewport-fit=cover，env(safe-area-inset-top/bottom)，顶部不被灵动岛遮挡、底部导航留手势空间。跟随系统主题，320/402/桌面宽度无横向溢出。页签蓝字下划线、主按钮实心/次按钮描边、单色线性图标；深色背景#000/卡片#1C1C1E/无阴影，浅色#F5F5F7/白卡片/轻阴影，主色#0A84FF。

## 3. 推荐实施阶段和每阶段门禁

1. 工程、设计 token、类型、数据库/RLS。双用户跨账号查询/插入/关联必须失败。
2. OTP 两类邮件 + 会话恢复；从 iPhone 已安装 PWA 内成功登录，不打开外链。
3. 基础记录/时间线/统计/设置；表单验证、重载持久化、混币正确处理。
4. 旅程编辑/范围外/状态/实际子记录；没有 orphan 或跨 owner FK。
5. 交通字典/双向航司/机型、时区和时长；纯算法 tests 全通过。
6. 全天/酒店投影、换店/重叠；更新一个 id 后各日同步变化。
7. Edge 身份、邀请、Owner、原子额度、并发/频率；先 mock 上游再少量实测。
8. 航班精确匹配/预览确认/防重复；未来日期调用次数为 0。
9. 五类 AI、缓存、手动降级、配额；日志不泄露文本与秘密。
10. 离线/账号切换/错误/冲突、安装安全区、发布与回滚演练。

不满足某项不要用“构建成功”代替该项验收。使用独立测试项目，测试真实服务须维护者批准并计算额度。

## 5. 灾难重建完成标准

新仓库可从干净 npm 安装构建；空 Supabase 可执行所有迁移且RLS验收；Owner/邀请码由新管理员安全初始化；全部端点与合同一致；OTP新旧用户+实机PWA成功；样例全部通过；功能与未实现边界在新指南清楚；在测试项目完成一次回滚/恢复。

原 Auth UUID 不保留则旧业务 FK 必须受控映射迁移，不能直接把旧记录认到新UUID。最后记录恢复了哪些数据、哪些未恢复、可复现版本与新服务配置。发布前由维护者确认。
